Plugins in a real sandbox: **!StayAlone** 1.2.6.

## What changed

- **Every third-party plugin now runs in its own Windows sandbox (AppContainer)**, the same isolation Microsoft Store apps get, on top of the existing Job Object:
  - it can only **read its own folder** and write to a data folder of its own (`STAYALONE_DADOS`); your documents, desktop and the rest of your account are out of reach;
  - **no internet** unless its `plugin.ini` says `internet = sim` and you approve it when turning it on (a plugin that starts asking for internet later is paused until you approve again);
  - it gets a minimal environment (none of your environment variables, API keys included) and inherits only its stdin/stdout/stderr.
- **Approved folders:** a plugin can ask for specific folders in its `plugin.ini` (`ler = Documentos\Notas` to read, `gravar = Downloads` to read and write, up to 5). You see each folder when approving; the whole user folder, AppData, hidden folders like `.ssh`, Windows, Program Files, ProgramData, drive roots and network folders are always refused. Turning the plugin off takes the access back.
- **New approval window** in the app's own look instead of the Windows message box: what the plugin is, whether it wants internet, what the sandbox guarantees, and the SHA-256 in blocks of 8. The focus starts on *Not now*.
- The *Security and privacy* card says how many plugins are on, how many have internet and how many have folders of yours.
- `plugin.ini` files saved with a UTF-8 BOM (PowerShell 5, old Notepad) no longer lose their first line.

**For plugin authors:** PowerShell doesn't know the current folder inside the sandbox; open your files with `Join-Path $PSScriptRoot "file.txt"`. A plugin that used the network or your files without declaring it will stop working until it declares what it needs (`internet = sim`, `ler =` or `gravar =`). The example plugin works unchanged.
