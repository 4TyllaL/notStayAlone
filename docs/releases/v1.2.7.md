A clean rebuild of **!StayAlone** 1.2.6: 1.2.7.

## What changed

- **Fixes the Microsoft Defender block on the 1.2.6 download.** Defender's machine-learning model flagged the 1.2.6 `.exe` as `Trojan:Win32/Sabsik.TE.A!ml`, so Chrome and Edge deleted the download (and auto-update from 1.2.5 couldn't finish). It was a false positive: the same code, compiled into a slightly different layout, isn't flagged. 1.2.7 has the same features as 1.2.6.
- **Truly reproducible builds.** Rust hashes the project folder into the crate, so a build made from another folder came out different. Releases are now built from a clean checkout of the commit, always at `C:\StayAloneBuild\src`; building the same commit there, with the toolchain listed in `BUILDINFO.txt`, gives the same SHA-256.
- The release script now scans the `.exe` with Microsoft Defender and refuses to publish anything it flags.

Everything from 1.2.6 is here: plugins in a Windows sandbox (AppContainer), approved folders (`ler =` / `gravar =`), internet only when you approve it, and the new approval window.

## Download

**[`dontStayAlone.exe`](https://github.com/4TyllaL/notStayAlone/releases/download/v1.2.7/dontStayAlone.exe)** — one file, the whole app (AI chat included). If you're on 1.1.x or 1.2.x, the app offers this update by itself. Windows 10/11, 64-bit; no installer, settings live in `%APPDATA%\StayAlone` and are kept when you update.

`dontStayAlone.exe.sig` is the update signature; the app downloads and checks it by itself, so you don't need it. `BUILDINFO.txt` is for anyone who wants to audit or rebuild the release.

> Why *dont*StayAlone? The app is **!StayAlone**, but GitHub strips the `!` from file names.

The binary is not code-signed (Authenticode) yet, so SmartScreen may warn on first run (*More info → Run anyway*). GitHub shows its SHA-256 next to the download.
